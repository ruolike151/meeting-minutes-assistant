## 1. 目标与验收口径

《技术方案》17 节对 M2 的定义是：**`perception/` 接入真实转写与声纹，`offline.py` 保留为测试后端。**

结合参考实现，M2 的验收口径具体化为：

1. 上传一段真实会议音频（mp3 / m4a / wav），跑完得到**带时间戳、说话人、声纹置信度**的结构化片段并入库，说话人来自声纹库的真实身份；
2. `offline.py` 仍是无 GPU 机器上的默认后端，`pytest` 在**无 GPU、无网络、无模型权重**的机器上全绿（约束 C3 不回退）；
3. 真实后端由环境变量开启，模型规格、参数、注册命令、降级路径全部写进 README；
4. 感知层有可复现的量化结果，且口径统一：窗口级说话人准确率、宏平均召回、转写 CER、端到端 RTF、显存峰值；
5. `register_speaker` 工具补齐（《技术方案》8 节已有契约，M1 未实现）；
6. 音频任务从"订阅即推进"改为**后台执行 + 状态落库**。

### 2.3 参考实现实测指标（ECAPA 后端）

| 指标 | meeting.mp3 | meeting2.mp3 | 双会议合计 |
| --- | ---: | ---: | ---: |
| 音频时长（秒） | 86.52 | 357.98 | 444.50 |
| 转写片段数 | 7 | 24 | 31 |
| 声纹窗口数（2.5s/1.25s） | 69 | 286 | 355 |
| 窗口级说话人准确率（排除 GROUP） | 93.75% | 91.70% | **92.08%** |
| 宏平均召回率 | 92.86% | 87.75% | **88.61%** |
| 转写 CER（tiny 模型原始输出） | 42.25% | 41.06% | **41.30%** |
| 转写 RTF（参考实现记录） | 0.1602 | 0.0246 | 0.1002 |

三条必须看清的结论：

1. **声纹链路已经可用**：窗口级准确率 92%，四人各自召回率 0.84–0.99，这套滑窗匹配算法值得原样移植；
2. **转写质量是当前最大短板**：tiny 模型中文 CER 42%，等于一半字错。这直接决定决策 ① 要不要换 small / medium；
3. **RTF 口径不可比**：meeting.mp3 在两次运行里分别记到 0.16 和 0.41，meeting2 记到 0.02（该次复用了历史转写结果）。M2 必须统一计时口径重测，否则指标没有说服力。

残留错误（来自参考实现的混淆矩阵）：C→D 混 3 次；meeting2 里 B/C/D 各有 8/9/8 个窗口被误判成 A（A 发言占比大，出现"强势说话人吸附"）；GROUP（多人合说）与 UNKNOWN 少量存在。

### 2.4 参考实现自己承认的短板

它的 README 第 9 节列了 5 条下一步，与我们 M2/M3/M4 正好衔接：升级模型、引入 pyannote 做分离、增加注册音频（建议 30–60 秒 / 人 / 多段）、低相似度与低 margin 的条目降级为 UNKNOWN 或 needs_review、把结构化结果交给 LLM/Agent 做摘要与待办抽取。

## 5. 关键算法（照搬参考实现，参数原样保留）

**注册**：单人录音 → 归一化 → 2.5 秒窗 / 1.25 秒步长的滑窗 → 每窗 ECAPA embedding（L2 归一化）→ 存**每人的 embedding 矩阵**与质心（不能用质心替代矩阵，因为匹配用的是 top-k 均值）。

**匹配**：会议滑窗 → embedding → 与每个注册人的全部 embedding 求余弦 → 取该人**相似度最高的 3 个求平均**作为该人的得分；最高分与次高分之差为 margin。

**置信度**：`0.65 * ((score + 1) / 2) + 0.35 * sigmoid(18 * margin)`。

**状态判定**：`score >= min_score(-1.0)` 且 `margin >= min_margin(0.005)` → `accepted`，否则 `needs_review`。

**轮次合并**：相邻同说话人窗口（间隔 ≤ hop）合并；一个轮次里 `accepted` 窗口占比 ≥ 0.5 才算 `accepted`。

**片段归属**：对每条转写片段，按"重叠时长 × 窗口置信度"对各说话人加权投票；无任何重叠窗口 → `UNKNOWN`，置信度 0。

**兜底编码器**：ECAPA 权重缺失或加载失败时回退 MFCC 统计特征（torchaudio），无需下载模型；本项目中它排在 `offline` 后端之后，仅作为 `local` 内部降级。

| 参数 | 默认值 | 可调位置 |
| --- | --- | --- |
| 窗口 / 步长 | 2.5 s / 1.25 s | `MA_SPEAKER_WINDOW` / `MA_SPEAKER_HOP` |
| top-k 均值 | 3 | `MA_SPEAKER_TOPK` |
| 最低分 / 最低 margin | -1.0 / 0.005 | `MA_SPEAKER_MIN_SCORE` / `MA_SPEAKER_MIN_MARGIN` |
| 轮次通过比例 | ≥ 0.5 | `MA_SPEAKER_ACCEPT_RATIO` |
| 最短窗口时长 | 0.8 s | 常量 |

前四个参数在 M2 结束时用标注集扫一遍，报告里给出前后对比（这正是《技术方案》"参数要能逐项调"的落地）。

## 6. 数据与存储（迁移 v2）

```sql
CREATE TABLE IF NOT EXISTS speakers(
    id         TEXT PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE,
    role       TEXT,
    encoder    TEXT NOT NULL,      -- 记录来源编码器：换模型后知道哪些向量失效
    dim        INTEGER NOT NULL,
    centroid   BLOB,               -- float32 小端字节流，便于快速粗略比对
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS speaker_embeddings(
    speaker_id TEXT NOT NULL REFERENCES speakers(id) ON DELETE CASCADE,
    idx        INTEGER NOT NULL,
    vector     BLOB NOT NULL,      -- float32 小端字节流，长度 = dim * 4
    PRIMARY KEY(speaker_id, idx)
);

CREATE TABLE IF NOT EXISTS tasks(
    id          TEXT PRIMARY KEY,
    filename    TEXT NOT NULL,
    path        TEXT NOT NULL,
    size        INTEGER NOT NULL DEFAULT 0,
    status      TEXT NOT NULL,     -- queued | running | done | failed
    stage_index INTEGER NOT NULL DEFAULT 0,
    stages      TEXT NOT NULL,     -- JSON 数组
    meeting_id  TEXT,
    error       TEXT,
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
```

向量编码统一走一对纯函数 `pack_vector(vec) -> bytes` / `unpack_vector(blob, dim) -> list[float]`，因此仓储层测试不需要 numpy。

每个任务独立可验收、可单独提交。T0–T2、T5、T6 不依赖 GPU。

- **验收**：`pytest` 全绿；`samples/` 与 `models/` 就位。

实施中相对本计划的显式偏差（都已写进代码注释）：

1. `PerceptionBackend.process()` 收**原始音频路径**，而不是 `NormalizedAudio`——
   离线后端必须能在没有 ffmpeg 的机器上跑通（约束 C3），标准化因此下移到各后端内部；
2. 转写直调 **faster-whisper** 而非 WhisperX：参考实现的 demo 实际没有启用强制对齐，
   而本项目只需要片段级时间戳（少一个重依赖与版本漂移源）；
3. 任务执行用**进程内单线程池 + `tasks` 表落库**，未引入外部队列：
   单机部署下"同时只跑一个任务"正是我们要的显存保护；
4. 合说（GROUP）不扩展领域模型，按未识别 + 低置信度处理，评测时单列统计；
5. `medium` 权重仍在后台下载，当前实测基于 `small`（模型规格是配置项，切换不需要改代码）。
