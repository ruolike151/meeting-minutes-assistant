# 会议纪要助手 · 傻瓜式操作教程

版本：v1.0　日期：2026-09-12　适用：Windows + PowerShell（macOS / Linux 把命令里的
`.\meeting_assistant\Scripts\python.exe` 换成 `./meeting_assistant/bin/python` 即可）

配套文档：[`README.md`](../README.md)（项目全貌）、[`docs/MVP技术报告.md`](MVP技术报告.md)（面试用）

## 0. 先看这里：三条路线，按需要选

| 我只想…… | 走哪条 | 需要什么 |
| --- | --- | --- |
| 3 分钟看到界面和效果 | **路线 A：零配置启动** | 什么都不用配 |
| 用真实录音跑一遍完整链路（转写 + 声纹） | **路线 B：真实感知** | 约 550 MB 权重；有 GPU 更快 |
| 跑评测、出报告 | **路线 C：评测** | 无 |

**所有路线都不需要 GPU、不需要 API Key、不需要联网**（下载权重那一步除外）。

## 路线 A：零配置启动（3 分钟）

### A1. 打开 PowerShell，进项目目录

```powershell
cd "E:\就业相关\我的项目\会议纪要助手"
```

### A2. 确认虚拟环境可用

```powershell
.\meeting_assistant\Scripts\python.exe --version
```

应该输出 `Python 3.12.x`。如果这一步报"找不到文件"，执行一次：

```powershell
python -m venv meeting_assistant
.\meeting_assistant\Scripts\python.exe -m pip install -r requirements.txt
```

### A3. 启动服务

```powershell
.\meeting_assistant\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到这两行就成功了（**这个窗口不要关**）：

```text
INFO:     Uvicorn running on http://127.0.0.1:8000
INFO:     Application startup complete.
```

### A4. 打开浏览器

访问 <http://127.0.0.1:8000>，你会看到三栏界面：

```text
┌──────────────┬────────────────────────────┬────────────────────────┐
│ 会议库（左）  │ 对话区（中）                │ 详情面板（右）          │
│ · 会议列表    │ · 输入问题                  │ · 纪要 / 待办 / 待确认  │
│ · 搜索        │ · 上传音频（回形针样式图标） │ · 原声（引用回跳）      │
│ · 待确认徽标  │ · 回答里带引用标签           │ · 导出                  │
└──────────────┴────────────────────────────┴────────────────────────┘
```

### A5. 试三个问题（中间对话区直接输入）

```text
官网改版周会定了什么？
这三场会有什么风险？
C 一共答应了哪些事？
```

你会看到：先出现阶段进度（"理解意图与查询范围 → 检索相关片段 → 组织回答"），
然后给出带引用标签的回答。**点击任意引用标签**，右侧会自动切到"原声"并高亮那一句。

> **提问范围怎么切？** 发言人用字母代号（真实录音 `A`–`D`，产品样例库 `A`–`E`）。
> 对话头部右侧有一个范围标签：
>
> * 默认是「**全部会议**」——问题会跨整库检索，可以问"这几场会有什么风险"；
> * 点左侧会议库里的某场会、或上传一段音频后，范围会自动限定到那场会，
>   标签变成会议标题，此时只会查这一场（问"还有什么待办"不会串到别的会）；
> * 想切回全库，**点一下范围标签**即可，当前对话内容不会丢
>   （「新对话」是另一回事：它会同时清空对话并重置范围）。

### A6. 上传一段音频（体验完整闭环）

1. 点输入框左侧的**上传音频**图标（回形针样式），选择 `samples\audio\meeting.mp3`；
2. 敲回车发送，进度条会依次走完四段：
   `音频标准化 → 16kHz 单声道` → `语音转写（WhisperX）` →
   `声纹识别与身份对齐（ECAPA-TDNN）` → `生成结构化纪要（Agent）`；
3. 处理完右侧自动切到**待确认**页签 —— 因为这条纪要里有条目没写负责人 / 没有截止时间，
   系统不会假装它是对的，而是交给人确认；
4. 点某条待确认卡片的**修改**，填负责人和截止时间，点"保存并确认"；
5. 全部确认完后，左侧会议库里的这条会议状态从"待确认"变成完成态。

### A7. 导出

右上角**导出**按钮，或直接用地址（把 `m_20260911` 换成你要导出的会议 ID）：

```text
http://127.0.0.1:8000/api/export/m_20260911?format=md     # 纪要 Markdown
http://127.0.0.1:8000/api/export/m_20260911?format=csv    # 待办 CSV（Excel 可直接打开）
http://127.0.0.1:8000/api/export/m_20260911?format=json   # 结构化结果
```

### A8. 收工

在启动服务的窗口按 `Ctrl + C` 停止。

## 路线 B：跑真实转写与声纹（可选，约 15 分钟）

> 不做这一步也能用：默认走"离线固定数据后端"，界面与流程完全一样，
> 只是转写内容是内置样例，不是真的在解码音频。

### B1. 安装感知层依赖（约 2.5 GB，第一次慢）

```powershell
.\meeting_assistant\Scripts\python.exe -m pip install -r requirements-perception.txt
```

有 NVIDIA 显卡就用 CUDA 版 torch（`pip install torch --index-url https://download.pytorch.org/whl/cu128`），
没有显卡用 CPU 版也能跑（实测 RTF 0.48，即 1 分钟音频约 29 秒转写）。

### B2. 下载权重（约 550 MB，走 hf-mirror 镜像）

```powershell
.\meeting_assistant\Scripts\python.exe scripts\download_models.py --sizes small
```

### B3. 注册四个发言人声纹（用项目自带的注册音频）

```powershell
.\meeting_assistant\Scripts\python.exe scripts\enroll_samples.py
```

### B4. 打开真实后端并重启服务

在项目根目录新建 / 修改 `.env`（可以从 `.env.example` 复制）：

```text
MA_PERCEPTION_BACKEND=local
```

然后重新执行 A3 的启动命令。再按 A6 上传 `samples\audio\meeting.mp3`，
这次进度条是真的在等模型跑。

### B5. 想验证感知层精度？（可选）

```powershell
.\meeting_assistant\Scripts\python.exe scripts\smoke_perception.py --meeting samples\audio\meeting.mp3
```

输出窗口级说话人准确率、宏平均召回、片段级准确率与 RTF。

## 路线 C：跑测试与评测

### C1. 跑全部测试（约 20 秒，384 项）

```powershell
.\meeting_assistant\Scripts\python.exe -m pytest -q --basetemp=.pytest_tmp
```

预期结尾：`384 passed, 1 skipped`（用例数会随迭代增加）。跳过的那一项是需要真实模型的感知冒烟，属正常。

### C2. 文档一致性检查（207 项）

```powershell
.\meeting_assistant\Scripts\python.exe tests\test_docs.py
```

### C3. 跑一遍完整评测（离线，约 2 分钟）

```powershell
.\meeting_assistant\Scripts\python.exe scripts\run_eval_all.py --offline --encoder hash --rerank
```

产物在 `data\eval\<运行ID>\`：

| 文件 | 内容 |
| --- | --- |
| `raw.json` | 逐条明细（哪条查询没命中、哪条引用被判不支撑） |
| `metrics.json` | 全部指标汇总 |
| `report.md` | 可直接读的报告 |

数字与结论已经整理在 [`docs/M5-评测报告.md`](M5-评测报告.md)（含失败归因）。

### C4. 分项评测（可选）

```powershell
.\meeting_assistant\Scripts\python.exe scripts\eval_minutes.py    # 纪要质量
.\meeting_assistant\Scripts\python.exe scripts\eval_dialogue.py   # 路由与多轮
.\meeting_assistant\Scripts\python.exe scripts\eval_retrieval.py --encoder hash --sweep
```

### C5. 想用真实大模型评测（可选，会花 token）

先在 `.env` 里填 `MA_LLM_API_KEY`，然后：

```powershell
# 1) 先预演，看要花多少
.\meeting_assistant\Scripts\python.exe scripts\run_eval_all.py --live --dry-run

# 2) 再真跑（MA_EVAL_TOKEN_BUDGET 是硬上限，超了直接中止）
.\meeting_assistant\Scripts\python.exe scripts\run_eval_all.py --live --encoder hash
```

```powershell
# 1) 装可选依赖

#    MA_LANGFUSE_HOST=http://127.0.0.1:3000
#    MA_LANGFUSE_PUBLIC_KEY=pk-lf-ma-local
#    MA_LANGFUSE_SECRET_KEY=sk-lf-ma-local
```

## 面试现场 5 分钟演示脚本

按顺序做这四步，每步都能落到一个"讲得出为什么"的点上：

1. **问一个带范围的问题** —— 输入"官网改版周会定了什么？"
   讲：意图路由把问题分到"结构化决议"路径，范围锁定到单场会议，没有走检索。
2. **问一个需要跨会议检索的问题** —— 输入"这三场会有什么风险？"
   讲：混合检索（BM25 + 向量 + RRF）、双闸拒答、相邻片段组装，回答里每个引用可回跳。
3. **上传音频，走完待确认闭环** —— 上传 `samples\audio\meeting.mp3`，确认一条待确认条目。
   讲：LangGraph 的 `interrupt` 挂起、检查点落盘、确认后 `Command(resume=…)` 恢复并收尾。
4. **打开评测报告** —— 展示 `docs\M5-评测报告.md`。
   讲：12 项指标、消融矩阵、失败归因；以及"离线基线 / 真实模型"两套数字的差别。

想加一段"防翻车"的话术：**没有 Key 也能演示**——把所有开关关掉，
链路自动落到"规则路由 + 混合检索 + 模板装配"，功能与流程一个不少。

## 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Address already in use` | 8000 端口被占用 | 换端口：`--port 8001`，或 `Get-NetTCPConnection -LocalPort 8000` 找到占用进程 |
| 界面上传后一直停在 0% | 后台任务失败 | 看服务窗口日志；或 `GET /api/tasks/{task_id}` 看 `error` 字段 |
| 上传后没有纪要内容 | 没配 Key（默认无模型） | 正常行为：模板装配会给出"待生成"提示；配 `MA_LLM_API_KEY` 后走真实生成 |
| 检索总是"没找到" | 阈值偏严或查询太泛 | 先确认会议库里确实有相关会议；调 `MA_MIN_COVERAGE` / `MA_MIN_COSINE` |
| 真实后端报缺少模型 | 没下载权重 | 跑 `scripts\download_models.py --sizes small` |
| 说话人全是"未识别" | 没注册声纹 | 跑 `scripts\enroll_samples.py`（或 `enroll_speaker.py` 注册自己的） |
| 想清空数据重来 | — | 停服后删掉 `data\` 目录（音频、库、检查点都在里面），重启会自动重建样例数据 |
| 界面里发言人还是旧名字 | 本地库里存的是改名前的显示名 | 跑 `.\meeting_assistant\Scripts\python.exe scripts\rename_speakers.py`（幂等，只改显示名；加 `--dry-run` 先预览） |
| 对话头部的范围标签点不动 | 已经是"全部会议" | 正常：只有在限定到某场会议时点它才会切回全库 |
| Langfuse 控制台是 500 | 只起了 web，缺 worker/Redis/MinIO | 用仓库里的 compose 整体 `up -d`（见路线 D） |

## 目录速查（想知道东西在哪时看这里）

```text
app/agent/      编排层：状态图、节点、提示词（graph.py 是唯一 import langgraph 的地方）
app/retrieval/  检索层：BM25 + 向量 + RRF + 重排 + 拒答阈值
app/perception/ 感知层：音频标准化、转写、声纹匹配（offline / local 双后端）
app/tools/      工具层：7 个工具（列会 / 取纪要 / 检索片段 / 发言人汇总 / 改待办 / 标待确认 / 处理音频）
app/eval/       评测层：数据集契约、指标、运行器、报告、证据判定
app/store/      SQLite 仓储与迁移（v1…v5）
web/            无构建前端（原生 HTML/CSS/JS，FastAPI 直接托管）
samples/        样例音频与标注；评测标注在 samples/annotations/m5/
docs/           产品文档、技术方案、各阶段计划与报告
scripts/        下载权重、注册声纹、评测、预热缓存等运维脚本
```
