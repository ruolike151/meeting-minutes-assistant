## 4. 消融矩阵

| 配置 | 编码器 | Recall@8 | MRR | 跨会议 | 域外拒答 | 域内作答 | 路由准确率 | 证据正确率 | 要点覆盖 | 待办 F1 | 检索 P95 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| RRF-only（M3 默认） | hash#256 | 0.875 | 0.697 | 0.625 | 0.938 | 0.900 | 0.871 | 0.347 | 0.432 | 0.889 | **0.5 ms** |
| + cross-encoder 重排 | hash#256 | 0.875 | **0.792** | 0.625 | 0.938 | 0.900 | 0.871 | 0.375 | 0.513 | 0.889 | **56.5 ms** |

### 重排结论（关闭 M3 决策 ③）

1. **MRR 0.697 → 0.792（+13.6%）**，Recall@8 不变（召回本来就够，重排改善的是排序）；
   证据正确率与要点覆盖率随之上升（0.347→0.375、0.432→0.513）——排名靠前的片段
   本来就更可能支撑结论，这是"排序质量影响答案质量"的直接证据。
2. **代价**：单查询检索 P95 从 0.5 ms 涨到 56.5 ms（CPU，`bge-reranker-base`，
   top-20 候选），整轮问答 P95 从 23 ms 涨到 3077 ms（离线环境下重排是主要耗时项）。
3. **按预注册门槛判定**（MRR +3%、延迟 +≤300 ms）：**两项都满足 → 重排是有效的质量升级**。
4. **默认值仍保持 `off`**：RRF-only 零权重、零额外依赖，任何机器克隆下来就能跑，
   是约束 C3 的基线；重排是"实测有收益的可选项"（`MA_RERANK_MODE=cross_encoder`）。
   本地 BGE 编码器 + 重排的第三行消融留给真实语料到位后补齐。

## 5. 失败明细与归因（比总分更有用）

### 5.1 检索：5 / 40 未命中

| 未命中查询 | 原因 |
| --- | --- |
| 前端开发现在卡在哪一步 | 改述与原文（"在等设计稿定稿"）几乎无字面重合，hash 编码器救不回来 |
| 三场会里分别有哪些待办 | 跨会议汇总型提问：需要多跳聚合，单轮混合检索做不到 |
| 谁在会议上被分配了任务 | 同上 |
| 各场会的下一步动作分别是什么 | 同上 |
| 有没有跨会议都出现的问题 | 同上（语义上要求"比较"，不是"检索"） |

**结论**：5 条未命中里有 4 条是"汇总 / 比较"型问题。它们不该由检索层硬扛，
正确解法是编排层的聚合节点（先按会议分组检索、再聚合、再合成）——列在下一步，不在 M5 扩。

### 5.2 证据正确率 0.347 的归因

离线运行的回答是模板装配（`MA_LLM_MODE=off`）：模板把检索命中的片段拼进答案，
**结论句是拼出来的，不是模型写的**，所以"结论 ↔ 片段"的关键词覆盖率天然偏低。
这不是"引用错了"（引用越界率 0.000），而是规则版判定器在模板回答上偏严。
两个数字必须一起看——真实模型运行与 `MA_JUDGE_MODE=llm` 的对照是把这项做实的前提。

### 5.3 跨会议检索准确率 0.625

口径是**严格**的：跨会议查询返回的片段必须全部落在允许的会议集合内。
失败的 3 条正是第 5.1 节里的汇总型问题——要么返回空，要么命中第三场会议的相关片段。
严格口径的价值是暴露"会不会串会场"，代价是惩罚了合理的相关召回；
报告保留严格口径，宽松口径（命中只要包含允许会议）留作下一步的补充指标。

### 5.4 路由：4 / 31 未过

| 未过查询 | 期望 → 实际 | 原因 |
| --- | --- | --- |
| 移动端体验专项讨论最后定了哪些事 | decisions → content | 规则覆盖"定了什么"，没覆盖"最后定了哪些事" |
| 孙悦这周要做什么 | speaker_tasks → speaker_speech | 发言人 + 任务意图的句式覆盖不足 |
| 那王强要做什么 | speaker_tasks → speaker_speech | 同上（也是多轮用例里唯一失败的一条） |
| 帮我总结一下这三场会议 | clarify → content | 泛指总结的澄清触发词没覆盖这种说法 |

四条全是**规则模式的句式覆盖问题**，不是架构问题：`MA_ROUTE_MODE=auto` 且配了 Key 时
由模型兜底；离线（纯规则）下这四条就是它当前的真实水平，报告不修饰。

### 5.5 拒答：1 条域外漏放、1 条域内误拒

* "世界杯什么时候开始" 被放行：覆盖率与余弦都没有同时低于阈值。
  域外拒答正确率 0.938（15/16），低于 0.95 的目标。M3 用 22 条标注扫出来的阈值
  在这份 56 条标注上偏松了一点，下一步是**在新标注集上重扫**（`scripts/eval_retrieval.py --sweep`），
  并把域外样本从 16 条扩到 30 条以上。
* "这几场会一共定了哪些事？" 被误拒：跨会议汇总型问题被检索闸门拦下，
  与第 5.1 节同源。

## 8. 局限与下一步

1. **语料是样例会议**（3 场 / 32 片段）：题材接近真实项目周会，但复杂度偏低；
   真实会议录音（脱敏）到位后按同一 schema 补入并重跑。
2. **纪要质量四项是占位数字**：离线运行模型关闭，回落到固定备用纪要；
   真实质量必须由 `--live` 给出，报告不拿占位数字下结论。
3. **证据正确率用规则版**：规则版在模板回答上偏严（第 5.2 节），需要 LLM 判定与人工抽样校准。
4. **跨会议"汇总 / 比较"型问题缺一层聚合**：5 条检索未命中 + 1 条误拒都指向同一件事——
   这类问题属于编排层（先分组、再聚合、再合成）；M5 只把它量化出来。
5. **阈值需要在新标注集上重扫**：M3 的 0.50 是在 22 条标注上扫出来的，
   56 条标注下漏放了一条域外问题（第 5.5 节）。
6. **重排默认关闭**：`off` 是零依赖基线；实测 +13.6% MRR 的可选项写在第 4 节，
   演示与真实素材评测时建议开启，但默认配置不引入 1.1 GB 权重依赖。
